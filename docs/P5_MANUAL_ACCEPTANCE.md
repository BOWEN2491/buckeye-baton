Use the coordinator's latest3001 preview only after its runtime report confirms P5. Automated tests use mock providers; the real provider configuration is separate. No public deployment or main merge is implied.

1. Switch to a Mentor, open **My expertise**, choose several of the five domains and save. Refresh: choices remain. Empty choices display **Expertise not set** and still allow Staff to refer manually.
2. As a student, publish a project with your own public GitHub repository root. An invalid URL is rejected before posting; unavailable/private GitHub data leaves the authored project saved with a retryable analysis message.
3. Wait for the private introduction draft. Open **Sources**: repository, actual commit/read time/files and truncation are visible. Edit sentences; Topics and Technologies remain read-only. Before confirmation, Explore uses the authored summary and **Topics pending review**.
4. Confirm the draft. Project header labels and Sources update immediately; Explore shows the reviewed introduction. Change project progress: public AI content falls back until the replacement is reviewed. Generate a newer draft from another tab: the old tab cannot overwrite it.
5. Ask a specific question with **Yes, ask Staff to refer a mentor**. The question saves first. As Kevin, open **Refer a mentor**: **Suggested mentors** eventually shows up to three candidates, independent relevance scores and current **Awaiting reply**. No Mentor is preselected. **View all mentors** and a human-written reason remain available if analysis fails.
6. Choose a Mentor and refer. Sarah/the chosen Mentor replies; the asker adds a follow-up. The queue load and suggestions update without replacing the original referral. A plain comment does not request a new classification.
