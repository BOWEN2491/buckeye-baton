## 固定数据与主线

沿用 Alex、Mia、行业 Mentor Sarah、OSU Staff Kevin 四个演示身份。准备三个虚构状态样例：Alex 的 Paused 来源项目、一个 Finished 项目和一个 Ongoing 项目。新版 ID 在实现时统一，不把旧 lesson ID 当作项目问题 ID。

主线建议：Alex 的校园报名系统完成基本表单，但通知功能未完成；交接材料包含暂停原因、重新做的建议、已有代码链接。Mia 接棒改进通知功能。

1. Alex 发布来源项目，填写进展后标为 Paused，填写原因、重做建议和可复用资料。刷新后保留。
2. Mia 通过 Explore 搜索/状态筛选找到项目，在项目页读完经验和讨论，不需要打开独立 Lesson。
3. 点击 Continue this project，填写方式、新项目名称与推进目标，创建属于 Mia 的 Ongoing 项目。原项目仍归 Alex 所有，状态不变。
4. 两个项目互有正确链接；来源显示后续项目、接棒方式、目标和当前状态。刷新后关系保留。
5. Mia 在新项目提问：“通知流程应该优先补邮件，还是先完成站内确认？如何验证？”
6. 切换 Kevin 后返回 Explore，通过 My workspace 进入该问题，选择 Sarah 并填写理由；问题下显示具名引荐。
7. 切换 Sarah 后返回 Explore，通过 My workspace 正式回复；问题下显示回复和引荐完成状态，刷新后仍在。
8. Mia 更新进展，填写成果与给下一组的建议后标为 Finished。Alex 从原项目看到后续项目的新状态，沿链接查看成果。
9. 全程保留经验、讨论和引荐，不显示伪造成功数量或 Verified 标签。

## 其他接棒方式

- 从 Finished 项目选择 Reproduce，填写重现目标/不同环境，创建新 Ongoing 项目。
- 从 Finished 项目选择 Improve，填写待改功能及理由，创建新 Ongoing 项目。
- 三种方式共用表单和权限规则；不覆盖原内容。阅读和借鉴不强制接棒。

## 状态、权限与异常

- 没有导师也能发布、暂停、完成、接棒；空状态清楚。
- Ongoing 无问题时展示目标和进展，有问题时突出求助。
- Finished 缺少成果或下一组建议，Paused 缺少原因或重做建议时，状态更新失败且输入保留。
- 返回 Ongoing 或切换其他状态，不删除旧总结、问题、回复、引荐和关系；问题不会自动关闭，旧待办仍能回复。
- Finished/Paused 也能提问；同一项目的两个问题各有正确回复和引荐，不串线、不出现嵌套多层。
- 所有角色可普通讨论；非 Staff 不能引荐，非指定 Mentor 不能完成别人的引荐。
- 非所有者不能编辑原项目；接棒者只能编辑自己的后续项目。
- 无效身份、无效输入、非 HTTP(S) 链接被拒绝，提示清楚。
- 身份切换回未筛选的 Projects 首页，未提交表单重置，已保存内容保留。
- 搜索无结果、没有经验/问题/接棒者/待办、加载及请求失败都有明确状态。

- 更新共用类型、迁移、后端与浏览器测试，再运行 typecheck、test:backend、build、test:e2e 和生产启动。

- 四种身份跑完主线，检查桌面和 390px 手机，无横向溢出、无客户端异常。
