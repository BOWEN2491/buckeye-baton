# Buckeye Baton：现阶段项目总览

更新：2026-10-24。本文用于快速理解项目；详细已批准规则见 MVP_SPEC.md，实际接口见 API_CONTRACT.md。

## 我们要解决什么

前一组学生完成或暂停项目后，经验、未完成部分和导师建议容易随团队散去。Buckeye Baton 让这些内容留在项目中，帮助下一组找到起点，并通过 Staff 连接合适的 Mentor。

**一句话定位：面向 OSU 学生的项目交接、接棒与导师连接平台。**

项目是一个团队负责的一次有明确目标的实践。经验直接嵌在项目里；代码通过 GitHub、演示和文档链接访问。

## 产品如何运作

浏览项目 → 阅读成果与经验 → 选择重现 / 继续 / 改进 → 创建自己的关联项目 → 提出具体问题 → Staff 引荐 Mentor → Mentor 回复 → 更新进展和成果 → 来源团队看见后续贡献。

| 项目状态 | 内容重点 |
|---|---|
| Ongoing | 目标、当前进展、项目问题与指导 |
| Finished | 成果、问题及解决方式、给下一组的建议 |
| Paused | 暂停原因、重做建议、可复用材料 |

Student 负责项目与经验、提问和推进；Staff 针对问题找人并说明引荐理由；Mentor 提供指导。导师参与不是发布或接棒的前提。

## 技术实现

- Next.js 15 App Router + React + TypeScript：页面和 /api 接口位于同一个应用。
- Tailwind 与自定义 CSS：沿用现有导航及三状态内容布局。
- Node.js 22；通过 pg 接入 PostgreSQL。当前运行使用显式启用的本地持久 PGlite，单数据目录只运行一个应用进程。
- Project.reflection 使用 JSONB 保存进展、成果、问题经验、下一组建议、暂停原因、重做建议和材料。新增字段的迁移可重复执行，旧记录不重置。
- 服务端校验所有者、输入和状态必填内容；PATCH 在事务内合并并校验后保存。
- 四个演示身份通过 x-demo-user-id 切换，属于演示机制，未实现真实认证。
- 总控对提交 61ff34b 独立通过类型检查、生产构建/启动、5 个后端测试和 7 个浏览器测试，P1 十项本地验收通过；详见 P1_ACCEPTANCE.md。真实 PostgreSQL 多连接、Neon/AWS 与公网部署未验证。
